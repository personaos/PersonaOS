# Story 1.3: Local TTS Integration (Mimic3/Coqui)

## Status
Draft

## Story
**As a** PersonaOS user,
**I want** PersonaOS to convert LLM responses and tool execution results into natural speech using local TTS,
**so that** I can receive audio responses while maintaining privacy and offline capability for complete voice conversations.

## Acceptance Criteria
1. Local TTS integration implemented in `core/tts/` directory using Mimic3 or Coqui TTS
2. Text-to-speech conversion works offline without external API calls
3. LLM responses are converted to natural-sounding speech output
4. Tool execution results and system messages are converted to audio
5. TTS can be enabled/disabled via configuration
6. Multiple voice models and languages are supported
7. Audio output integrates with system audio playback
8. Streaming TTS for real-time response during long LLM generations
9. Error handling for TTS failures with fallback to text display

## Dev Notes

### Previous Story Insights
**Dependencies**: 
- Requires Story 1.1 (Local STT Integration) for complete voice pipeline
- Requires Story 1.2 (Audio Pipeline Controller) for orchestration integration

### Current System Architecture
[Source: PersonaOS_Spec.md#runtime-workflow]
- Current workflow ends at LLM/Tool output → TTS will extend this to → Audio Output
- TTS integrates at the response stage of existing intent processing pipeline
- Must work with both streaming and non-streaming LLM responses from multi-backend system

### File Locations and Project Structure
[Source: CLAUDE.md#core-architecture]
- **Primary TTS implementation**: `core/tts/local_tts_handler.py`
- **Audio utilities extension**: `core/audio.py` (shared with STT)
- **Configuration updates**: `.env` template and `core/config.py`
- **Integration point**: `core/voice/voice_pipeline_controller.py` (from Story 1.2)

### Integration Points
[Source: CLAUDE.md#llm-integration]
- **LLM Manager**: `core/llm/llm_handler.py` - Multi-backend system with streaming support
- **Voice Pipeline Controller**: Integration point for TTS in voice conversation flow
- **Tool Execution Results**: `core/tools/` - Tool output must be converted to audio
- **Memory System**: `core/llm/memory.py` - TTS may need conversation context

### Technology Stack Requirements
[Source: PersonaOS_Spec.md#appendix-ovos-integration-plan]
- **Mimic3 TTS** - Listed as planned high-quality offline speech synthesis
- **Alternative: Coqui TTS** - Open-source TTS with good offline capabilities
- **Audio playback library** - For system audio integration
- **Streaming support** - For real-time audio during LLM generation

### Technical Constraints
[Source: PersonaOS_Spec.md#goals-philosophy]
- **Local-first approach** - No external API dependencies, fully offline
- **Privacy-focused** - All TTS processing must remain on local hardware
- **Modular design** - TTS component must be pluggable and replaceable
- **LLM-native** - Must work with existing multi-backend LLM system

### Existing Component Integration
[Source: CLAUDE.md#direct-model-execution-dme-system]
- **Streaming Generation**: LLM system supports `generate_streaming()` for real-time tokens
- **GPU Acceleration**: TTS should consider GPU usage alongside existing LLM GPU usage
- **Hot-swapping**: TTS should support runtime configuration changes like LLM backends
- **Memory Management**: Proper model loading/unloading for TTS models

### Performance Considerations
- TTS processing should not block LLM generation or user input
- Streaming TTS should minimize latency for responsive conversations
- TTS model loading should be optimized (preload commonly used voices)
- Audio buffer management to prevent audio dropouts or delays

### Audio Integration Requirements
- Must work with existing audio utilities in `core/audio.py`
- Should not conflict with STT audio input processing
- Need proper audio device management (input/output separation)
- Volume control and audio quality settings

### Testing Standards
[Source: CLAUDE.md#development-guidelines]
- **Unit Testing**: Test TTS handler methods and audio integration
- **Integration Testing**: Test TTS with LLM pipeline and voice controller
- **Performance Testing**: Measure TTS latency and streaming effectiveness
- **Mock Testing**: Use mock audio output for consistent testing

### Security and Privacy Considerations
- TTS processing should respect existing privacy settings
- Generated audio should not be stored unless explicitly configured
- Voice model files should be validated for security
- Audio output should respect system audio permissions
